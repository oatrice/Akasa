## Summary

This PR adds support for displaying AI model information in task notifications to enhance transparency and debugging capabilities for users.

## What Changed

### Core Model Updates
- Added optional `model` field to `TaskNotificationRequest` in `app/models/notification.py`
- Updated status field formatting for better readability

### Backend Logic
- Modified `app/routers/notifications.py` to implement model resolution logic:
  - External AI use case: Uses model from payload directly (e.g., "SWE-1.6" from Windsurf)
  - Local AI use case: Retrieves user's model preference from Redis when no model provided
- Added `get_user_model_preference` import and logic

### Notification Display
- Enhanced `app/services/telegram_service.py` to display model information:
  - Added `*Model:* {escaped_model}` line when model is present
  - Improved error handling and logging for notification sending
  - Added testing mode with `DISABLE_TELEGRAM` environment variable

### MCP Server Integration
- Updated `scripts/akasa_mcp_server.py`:
  - Added `model` parameter to `notify_task_complete` function
  - Updated MCP tool schema to include optional model field
  - Fixed type hints for better compatibility

### Testing & Documentation
- Added comprehensive tests across multiple files:
  - Router tests for model preference retrieval
  - MCP server tests for model parameter handling
  - Telegram service tests for model display
- Created extensive documentation:
  - Feature specification (`spec.md`)
  - Implementation plan (`plan.md`)
  - Analysis document (`analysis.md`)
  - Manual verification guide (`manual_verify.md`)
  - Scenario examples (`sbe.md`)
- Updated CHANGELOG.md with new entry
- Updated README.md to highlight model transparency
- Updated ROADMAP.md and VERSION

## Why This Matters

Users currently receive task notifications showing the source (e.g., Antigravity, Windsurf) but lack visibility into which AI model generated the results. This creates challenges for:

- **Debugging**: Understanding why certain models produce specific outcomes
- **Model Selection**: Making informed decisions about which models to use
- **Transparency**: Building trust in AI-generated content

This feature addresses these needs by displaying model information alongside source information, providing complete context for each task notification.

## Implementation Notes

- **Backward Compatibility**: All changes are optional and maintain existing behavior
- **Model Resolution**: Priority order: Payload model > Redis preference > None
- **Safety**: Uses `escape_markdown_v2_content` for safe Telegram display
- **Testing**: Comprehensive test coverage including edge cases
